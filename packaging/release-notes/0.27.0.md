## New

- **Clear Context begins a new session in an agent's harness.** It is in a pane's and an agent
  row's right-click menu and in the Pane menu, and available as `muster pane clear otter` and the
  API's `pane.clear`. Claude Code and Codex are supported; OpenCode is not. The `clear_pane`
  action ships with no chord. Muster types `/clear` once the agent is idle at an empty prompt.
  `--then "<prompt>"` gives it its next task afterward. Codex reports the new session only at
  its first prompt afterward: restarting the pane before then brings the old conversation back,
  so give it that prompt with `--then`.
- **A pane hidden and then shown goes back where it was.** If its tab is unchanged, it takes
  its old place; otherwise it goes beside a former neighbor, or at the end of its old tab. It
  used to come back in a tab of its own, and still does if its old tab is closed, hidden or spans
  machines. A hidden tab holding several panes is still shown whole; helpers keep their shared
  tab.
- **`muster msg post --no-reply` marks a message that wants nothing back**, such as "stand by"
  or "nothing further". It still wakes the agent, but a helper that reads it and ends its turn
  without posting is not reported to its maker as gone idle without posting. The API takes the
  same mark as `NewPost.no_reply` and gives it back in history.
- **Pane verbs take the pane bare**, such as `muster pane close otter`, `muster pane read otter`
  and `muster pane wait otter llama`. This also works for `restart`, `hide`, `show`, `quiet`,
  `reattach`, `compaction`, `remove` and `reopen`. `--pane` still works; giving both is refused.
  `send`, `compact` and `rename` still need `--pane`, since their bare words already mean text,
  what to keep or a name.
- **`muster pane wait --until reading` waits for a stuck pane to read its input again.** It
  answers at once for a pane that is not stuck. If its daemon stops answering, the wait exits 4.
  Other waits still fail when their pane becomes stuck, unless they asked for `stuck`.
- **Muster tells you once of a pane left at a dialog for two hours**, even with no message
  waiting on it. The notice comes from `@muster` in your conversation with the pane and gives the
  command that brings it forward. Quiet panes stay quiet; helpers keep their existing notices.
- **`muster window` says why a message's wake is held**, such as a draft in the agent's prompt
  or a menu covering it. The pane's row adds `(a wake waits: <why>)`, and `--json` gives the reason
  as `wake_held`.
- **Mark as Unread on an agent's row** has it keep asking for you until you next look at it.
  Right-click the agent in the list, or run `muster pane unread otter`. The mark holds while the
  pane stays in view and ends when the pane has been out of sight and is seen again, or when its
  agent starts new work. Only an idle agent can be marked.
- **A tab can be hidden whole, with every pane in it.** Right-click the tab and choose Hide Tab,
  or run `muster tab hide --tab <id>`; the `hide_tab` action ships with no chord. Showing any of
  its panes brings the tab back with its splits, after the window's other tabs. With no `--tab`,
  `muster tab hide` hides the tab the window's keyboard is in, so an agent should name its tab.
- **Window > Hidden Panes lists every hidden pane** with its agent's state, and picking one
  brings it back with the keyboard on it. The list used to be reachable only from the sidebar.

## Changed

- **The daemon protocol is 1.16 and the API is 0.5.** Updating Muster runs a daemon handover;
  your panes and agents keep running. On an SSH host, Muster copies and starts the new daemon
  when it attaches; a daemon configured by `socket` needs updating separately. An older daemon
  cannot clear context. `muster pane send` still exits 0 for a send it could not queue, and
  `--no-reply` can still earn a helper a notice that it went idle without posting. API clients
  can check the API's Welcome message for `pane.clear` and `msg.post.no_reply` before using them.
- **Muster refreshes an installed local Codex adapter at app launch when its content changes.**
  It runs your interactive login shell once in the background to read your environment, then
  checks and refreshes the copy. A copy that is unchanged, or differs only in Markdown, is left
  alone. First installation and adapters on remote machines still need `muster harness install
  codex`. A Codex plugin marketplace registered from another source, such as a checkout, is left
  alone. Refresh never changes `daemon_auto_start`. After a refresh, restart Codex and review
  the changed hooks in `/hooks` before trusting them; running sessions keep their loaded adapter.
- **`muster pane send` reports a send the daemon could not queue**, whether the CLI reaches
  the daemon through a window or directly. It exits 1 with the reason, such as an agent
  restarting or a full input queue, instead of exiting 0 with nothing typed. A lost answer exits
  4: the send may have been typed, so read the pane before sending again.
- **`muster-daemon report --pane` takes a callsign or name as well as a pane id.** A report
  that times out or loses its connection now says whether it may have landed: exit 1 means
  nothing was reported, and exit 4 means to read `muster window` before reporting again. A report
  with `--waiting` waits up to 10 seconds for its answer, instead of 2.
- **`muster pane send` presses at most 32 keys in one send** and refuses more with nothing sent.
  While a send's keys go out, the pane's replies to terminal queries are written at once instead
  of waiting behind them.
- **A stuck agent's dot is purple.** It was pink, which read as the red of a full context ring.
- **An open conversation with one agent is titled with the agent's name**, as its banner already
  was, instead of the group's name.

## Fixed

- A helper that already reported is no longer reported as gone idle without posting after a
  turn that did not start with new work. A post to anybody counts as its report, and a helper
  waiting on its own working, waiting or blocked helpers is not reported as idle without posting.
- An agent closing a pane on the same machine with `muster pane close` no longer gets a "has
  not read" notice for its own unread messages to that pane. Messages from other agents are
  still reported to them, and a pane whose agent exits on its own is still reported.
- Stall notices and the time a dialog has waited are carried across daemon handovers. A newer
  daemon keeps track of notices already delivered. It does not restart the half hour a helper
  waits at a dialog before the person is told.
- A Return or Esc that a dialog ignores no longer raises a second banner or tells a helper's
  maker again when the pane reads blocked once more. The dialog keeps the time it first blocked.
- A message posted while no agent could be found in a pane wakes the agent once one is there
  again, including after an agent exits and is restarted, or after a folder-trust dialog.
- Codex reads working while its Stop hooks still prevent commands. It used to read done before
  those hooks finished, even though it could not yet accept `/clear`.
- Codex's new-model migration dialog reads blocked whichever option is selected. An ordinary
  reply discussing the migration's options stays idle.
- Environment variables given by `muster pane restart --env`, or an API restart, survive a
  daemon restart and Reopen Pane. Their values are kept in the daemon's private state file,
  `~/.muster/daemon/<install>.state.json`, not in pane records or the run log.
- Claude Code resumed after a restart or Reopen Pane drops a `--settings` or `--mcp-config`
  flag whose file has gone, instead of exiting immediately and leaving a shell. The pane's
  record says which flags were dropped.
- A wait declared with `report --until-exits` ends when its process becomes a zombie or another
  process reuses its pid, instead of waiting indefinitely.
- `muster pane send --enter` submits at a shell that a crashed program left in the kitty
  keyboard protocol, after `--key` presses too. A program that asks for that protocol still gets
  its own Return encoding, including one running under a shell with job control off.
- A conversation's date dividers put each message under the day its own time shows, including
  across a daylight saving change.
- Posting to a linked pane's former name says what it is called now, instead of saying nobody
  has that name.
- An agent that takes a name while a group's machine is unreachable, then leaves every group,
  no longer leaves its pane listed in that machine's groups when that machine is reachable again.
- When the CLI gets no answer from a window and asks the daemon instead, `--json` puts that
  warning in the answer's `note` field, instead of a second JSON document on stderr. Watches
  still put the warning on stderr.
- Harness install dry runs print their plan without running the harness, so a Codex marketplace
  query can no longer hold a dry run up.
- A dialog that ignores a Return or Esc no longer makes a program on the API's attention topic
  see the pane stop asking and ask again.
- `muster msg post` to an agent on another machine says what that agent is doing and why its wake
  waits, as it already did for an agent on the same machine.
- Making or moving a pane into a tab that spans machines no longer fails once when another change
  to that tab lands at the same moment.

Changes to the test suites and the build that do not reach an installed Muster are not listed.
