## Behaves differently

- **A group opens as its conversation, drawn in place of the window's panes, and the transcript pane
  is gone.** The banner's Open, the sidebar's group row, the macOS notification, ⌘⇧A and `muster
  msg open --group G` all show it (New, below). `muster msg open` now prints the window it showed
  the group in, where it printed a transcript pane. A pane you run `muster msg log --follow` in
  yourself is an ordinary pane and no longer counts as you reading the group.
- **`muster window --json` describes each tab as one tree.** `regions[]` and `tabs[].regions` are
  gone: a script reading them reads `tabs[].layout`, the tab's whole tree with the machine running
  each pane on its leaf, and `tabs[].zoomed`, the pane filling a zoomed tab. `--json` also says
  which group's conversation a window shows, as `conversation`, or null.
- **A post to an idle agent that was already woken rings it again**, and `post` prints "woke"
  rather than "already woken". After `/new` or `/clear`, or a turn that ended without reading, the
  agent sat idle at its prompt with the message unread and nothing would ring it. An idle agent now
  costs one turn per post; posts that arrive while it works still cost one wake between them.
- **An agent started inside a pane's agent can no longer read or wait on that pane's messages.** A
  `claude -p` or `codex exec` inherits `$MUSTER_PANE`, and with the messaging hooks installed it took
  the pane's unread messages into its own context and marked them read, so the pane's agent never
  saw them. Its `muster msg read` and `wait` are refused, naming both agents; `env -u MUSTER_PANE`
  in front of the nested command makes it a session of its own. Its posts still act as the pane.
- **`muster msg` through Codex's shared app-server is refused**, as its reports already were. The
  app-server carries the `$MUSTER_PANE` of whichever session started it, so a post from one pane's
  Codex went out as another pane, and the messaging hooks handed one pane's messages to another
  pane's session. `codex features disable daemon_auto_start` is the fix, and `muster harness
  install codex` sets it.
- **A group made again under a deleted group's name numbers on from the deleted group's last
  message**, rather than from #1, so no number in a group ever means two messages.
- **A Claude Code pane whose plugin is not installed reads `adapter: silent`** in `muster window`.
  The statusline's report alone used to count as the adapter reporting, so nothing said the hooks
  were missing. `muster harness install claude-code` installs them.
- **Return or Esc at a dialog makes the pane read `working` until its screen changes**, rather than
  `blocked` until the next look. A `muster pane wait --until idle,blocked` sent right after
  answering a dialog used to be answered "blocked" by the dialog the key had just closed. A screen
  that never changes reads blocked again after five seconds.
- **A new tab or split beside a pane whose directory has been removed starts at your home
  directory.** Every ⌘T was refused there. A directory you type, as in `muster tab new --cwd
  /nope`, is still refused.

## New

- **Muster draws its own banner for a message to you while it is in front**, at the top right of
  the panes: the group, the author, the time, the message's first lines with their Markdown drawn,
  and a reply field addressed to the author. ⌘↩ sends (`send_message` in `[keymap]`), Return writes
  a new line, and Esc gives the keyboard back to the pane. The macOS notification is posted only
  while Muster is behind, or while no window can draw the banner. `[notifications] messages =
  false` and mute silence both. A link in a message opens under the same rule as a cmd-clicked link
  in a pane, so a file that could run code is refused.
- **A group's conversation**, shown in place of the window's panes with the panes left running
  underneath: the thread with an Unread line, date dividers and runs of agent-only messages folded,
  a members column saying what each member is doing and why it has not read what waits on it, and a
  message box that posts as you, with @name completion and Urgent. Esc leaves it
  (`leave_conversation`), and so does `muster msg close`. The sidebar marks the members' panes while
  it is shown, and a draft in the box survives leaving, quitting and upgrading. Muster reads the
  group for you only while its conversation is in the focused window in front.
- **Questions with answers to pick.** `muster msg post --option "Run it now" --option "Skip it"`
  offers answers, up to six. The banner and the conversation draw them as buttons: picking fills the
  reply as `Answer: <answer>`, Send posts it with an optional note, Tab reaches the buttons from the
  reply field, and no digit picks one, so a reply can start with "1.". From a terminal, `muster msg
  read` and `log` list the answers, and `muster msg post --group G --answer Q:N` picks one. A
  question takes one answer.
- **`muster msg log --last N` and `--before N`** page a group's log, newest first.
- **A pane can go anywhere in a tab, whatever machine runs it.** A devenv pane can sit above or
  below a laptop pane, not only beside the laptop's panes as a strip of its own. `muster pane new
  --daemon devenv --down` and Split on Machine split the pane you are in; dragging a pane by its
  handle onto another machine's pane, or `muster pane move --onto P --side`, puts it on that side.
  Every divider, resize, zoom and equalize works across machines in such a tab.
- **Undo, Redo and Cut in Muster's own text fields**: a banner's reply, the message box, the find
  bar and the rename sheet. With no field holding the keyboard, ⌘Z, ⇧⌘Z and ⌘X still reach the pane.
- **A pane's old name, from before a rename, says what the pane is called now**, with its callsign
  and id, for the pane verbs and for `muster msg --to`. An agent addressing itself by
  `$MUSTER_PANE_NAME`, which keeps the name a pane started with, was told the pane had closed.
- **With `--group`, a `--to` name several agents answer to means the one in that group**, rather than
  being refused.
- **A refused action says why in the window.** New tab, split, close, move, compact and the drops
  beep and show a sheet with the reason, where they used to fail silently. Chords that repeat while
  held, such as resize and focus steps, only beep.

## Fixed

- **A maker is no longer told its Claude Code helper went idle without posting when the helper only
  compacted itself while idle**, which Claude Code does about an hour after its last turn. Needs the
  updated Claude Code adapter (Under the hood, below).
- **`/clear` in Claude Code resets the context `muster window` shows**, which kept the old
  session's percentage. Needs Muster's statusline, which updates with the app.
- **A maker hears when its helper's declared wait ran out after 10 minutes**, in those words, rather
  than a guess that the turn ended on an error, and is not told the same idle twice.
- **A wake typed into a prompt that never took its Return is erased once its messages are read**, so
  the next Return somebody presses no longer sends an out-of-date wake.
- **A member holding up a group kept on another machine is reported**, as in a group kept on this
  one. Councils across the laptop and a devenv went untold.
- **Joining a group on another machine under a new name** no longer renames you when that machine
  refuses the join, is retried when that machine was unreachable, and keeps your place when the
  answer is lost. After a daemon restart, a Codex agent that had joined by name no longer reads and
  posts as its pane.
- **A `--to` name several agents answer to is refused naming each by a ref that reaches it alone**,
  where one of the refs offered was the name that had just failed. The same name on a linked
  machine is refused too, rather than reaching whichever pane it found first.
- **A "held-wake" notice says how long the helper has really been working**, which could read as a
  day.
- **`post` says a wake is held behind a draft** when another look already had that agent's wake in
  hand, rather than "woke".
- **ctrl+/ reaches the pane** as ctrl+_, for Emacs's and readline's undo.
- **A command refusing `--window`** says what it does without the flag, rather than how to reopen a
  window that was open.
- **A handover to a newer daemon keeps a pane's waits, the turn Muster typed and a pending blocked
  report**, which each changed what the pane read afterwards.

## Under the hood

- The daemon protocol is 1.8, up from 1.7; the detection engine stays at 17. Muster hands the
  running daemon's panes to the new one on the first launch after updating, on the laptop and on a
  devenv, so running agents keep running. A question or an answer posted to a group kept by an older
  daemon is refused, rather than kept without its answers.
- The Claude Code adapter gains a hook for the compaction Claude Code starts by itself. Update it
  with `claude plugin marketplace update muster`, then `claude plugin update muster@muster`.
- Protocol 1.8 completes MIP-8, panes from any machine anywhere in a tab
  (`docs/mip/0008-panes-across-machines.md`), and carries MIP-9, the conversation and banner
  (`docs/mip/0009-group-conversation.md`).
- Changes to building and testing Muster itself are in the commit log, not here.
