## Behaves differently

- **A Codex wake that Muster hands over through `codex queue` waits 20 seconds before Muster types
  it**, up from 5. A Codex running without its shared app-server checks its queue about every 10
  seconds, so Muster often typed a wake that Codex still held, and the agent was woken a second
  time for a message it had already answered. A wake can now take up to 20 seconds to start a turn.
- **A declared wait from Codex, or from any harness whose finished background jobs do not start a
  turn, ends after 10 minutes.** It used to stand until somebody prompted the agent, with the pane
  reading `waiting` and a helper's maker told nothing. Claude Code's waits are unchanged, since its
  finished shells start its next turn. A wait declared with `--until-exits` (New, below) has no
  limit.
- **A wake or a compaction Muster types no longer ends a wait the agent declared.** Claude Code's
  prompt hook reports every prompt as ending the wait, so a helper rung for a message mid-build
  read idle with its build still running, and its maker was told it had gone idle without
  reporting. A prompt somebody types, and a finished background task, still end it.
- **A `blocked` report from an agent's hooks counts once the screen has been still for a
  second**, or once the screen shows the prompt. Claude Code and Codex report a permission request
  while the turn is still running, sometimes for approvals that never show a dialog, so a pane
  read `blocked` for up to three seconds with nothing on screen, and `muster pane wait --until
  blocked` could answer before the dialog was there to press keys at.

## New

- **`report --waiting "<what>" --until-exits <pid>` declares a wait that ends when the process
  exits**, and Muster then tells the agent so in a message from `@muster`, which wakes it as any
  message does. It is for Codex, which starts no turn when a background job ends. Update the
  Codex adapter to have Codex agents told about it: `codex plugin marketplace remove muster`, then
  `muster harness install codex`.
- **`muster daemons` gives each daemon's version**, in its headline and as `version` in `--json`.
- **A window says when another install's daemon holds panes on this machine.** A bundle put in
  place of the installed Muster without being built for its install starts a new, empty daemon
  beside the one holding every agent, and the window opened on one blank pane and said nothing.
  It now shows an error naming the other install, its version, its pane count and its socket.

## Fixed

- **⌘F opens and closes the find bar, and what you type goes into its field.** The field often
  never took the keyboard, so typing went to the pane, and a second ⌘F did not close the bar.
- **Ctrl+Return reaches the pane**, so Claude Code's ctrl+return to send a queued line works.
- **A message `@muster` sends a maker about its helper no longer blocks the helper's next post** as
  unread. A helper told to post and stop took that refusal as final and never reported.
- **A maker is no longer told its helper went idle without posting** after compacting an idle
  helper, after the helper answered a folder trust or picker dialog at an idle prompt, or when the
  helper posted from a dialog that a slow look saw before it saw the helper working.
- **A maker busy answering its helpers' dialogs is told a helper is blocked only once it is free
  to hear it**, and only if the helper is still blocked. It used to hear, at the end of its turn,
  about dialogs it had already answered.
- **`muster pane compact --then` types its prompt again.** In 0.17.0 the daemon gave up every
  compaction of an agent that reports through hooks, and dropped the prompt with it, though the
  compaction itself ran.

## Under the hood

- The daemon protocol is 1.7, up from 1.6, and agent detection engine 17, up from 16. Muster hands
  the running daemon's panes to the new one on the first launch after updating, on the laptop and
  on a devenv, so running agents keep running.
- Protocol 1.7 also carries the first two steps of MIP-8, panes from any machine anywhere in a tab
  (`docs/mip/0008-panes-across-machines.md`). Nothing a person sees changes yet.
- Changes to building and testing Muster itself, including `tools/install-main`, are in the commit
  log, not here.
