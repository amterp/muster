## New

- **A canvas is a pane that draws a document instead of running a terminal.** An agent opens one
  beside its own pane to show a plan, a diff summary, a diagram or a table, and replaces the
  document as its work moves on, while you read it without leaving Muster. A document is Markdown,
  HTML or an image (PNG, JPEG, GIF, WebP or SVG), up to 4 MiB, with a title of up to 256 bytes
  shown in the pane's header.

  ```sh
  muster canvas open plan.md --title "Migration plan"
  muster canvas write plan.md
  muster canvas read --pane otter --output plan.md
  ```

  `open` splits the calling pane to the right and prints the canvas's callsign; `--left`, `--up`,
  `--down`, `--tab` and `--pane` place it elsewhere, and the keyboard stays where it was unless
  you pass `--focus`. `write` replaces the whole document, and with no `--pane` it finds the one
  canvas the calling pane opened. `read` gives back the original bytes. All three work on an SSH
  machine and with no window open. `muster docs canvas` is the reference.
- **A canvas is a pane like any other**: it splits, moves, hides, takes a callsign and a number,
  and closes with `muster pane close`. It stays open when the pane that opened it closes. Its
  document and revision survive quitting Muster, a daemon restart, a daemon handover, and a close
  followed by Reopen Pane.
- **What a canvas page may do is fixed.** It loads nothing from the network or from disk: an image
  or stylesheet a page needs has to be embedded as a `data:` URI. Page scripts do not run. You can
  scroll, select and copy, but not edit. A link you click opens in your browser, for `http`,
  `https` and `mailto` only. Find (Cmd+F) does not search a canvas yet. `muster docs limits` has
  the list, and `docs/observations/webkit-21624.1.16.11.4.md` in the repository records what was
  measured, on macOS 26.4.1 only.
- **The API gains `pane.new_canvas`, `pane.write_canvas` and `pane.read_canvas`**, and a pane's
  record gains its canvas's kind, title, size and revision, so a program watching panes sees a
  revision move. `NewCanvas` names its placement, `new_tab {}` or `beside` a pane with a side and a
  ratio; one that names neither is refused. A write that replaced the document but could not be
  confirmed durable is answered `UNKNOWN`.

## Changed

- **The daemon protocol is 1.17 and the API is 0.6.** Updating Muster runs a daemon handover; your
  panes and agents keep running. The new daemon waits for the old one to exit before it answers,
  which takes about a second when updating from 0.27 and is not noticeable between later versions.
  On an SSH host, Muster copies and starts the new daemon when it attaches; a daemon configured by
  `socket` needs updating separately, and one older than 1.17 refuses canvas commands by name and
  version. API clients can check the API's Welcome message for `pane.new_canvas` before using it;
  a 0.5 client sees a canvas as a pane it cannot send to or read.
- **Going back to 0.27 while a canvas exists starts that daemon with no panes.** A canvas that is
  open, or was closed within the last hour, makes the daemon save its state in a format 0.27 does
  not read. 0.27 leaves that file alone, so updating again brings the panes' layout back. Close
  your canvases and wait out the hour, or expect an empty window, before rolling back.
- **`muster window` lists a canvas with the state `canvas`** and its title, and `--json` gives its
  kind, title and revision. Commands that need a terminal or an agent, such as `pane send`,
  `pane read` and `pane wait --until idle`, refuse a canvas and say that it is one. A message
  posted to a canvas's callsign is stored and answered as having no agent to wake.

## Fixed

- A split whose new pane was given a very small share could leave the daemon unable to save its
  session at all, so nothing made afterward came back after a restart. A left or up split with a
  tiny ratio, and reopening a pane closed out of such a split, now stay saveable. The API's
  `beside` placement takes a ratio from any program, which is how this was found.

Changes to the test suites and the build that do not reach an installed Muster are not listed.
