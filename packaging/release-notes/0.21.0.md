## New

- **Bring back a pane closed by mistake.** Reopen Closed Pane in the Pane menu, on ⇧⌘T, brings
  back the pane that window closed most recently, and Recently Closed beside it lists the others. A
  pane comes back under its name and callsign, in its directory and its place in its tab, with its
  agent running its session again with the flags it ran with, and its messages reach it as before.
  What was on its screen is not kept. `muster pane reopen --pane otter` does it from a shell, and
  `--list` lists what can be reopened. A pane somebody closed is remembered for an hour, and
  `reopen_closed_minutes` in the config changes that; `0` remembers none.
- **Answer a question in your own words.** A question an agent asks you no longer has to be
  answered with one of the answers it offers: a reply in your own words, typed or dictated, settles
  it the same way. Its buttons go, its banner comes down, and the agent that asked reads `Answer:`
  and then your words, as it reads a picked answer. A question still takes one answer, so a second
  of either kind is refused. In the conversation, a question answered this way says "Answered by
  you in words", and your reply is the row beneath it.
- **A program answers in your words through API 0.3.** `msg.post` answers a question in the post's
  own words when its `answering` names the question and no answer, and refuses one with no words.
  A daemon that serves this lists the option `msg.post.answer_in_words` in its Welcome, so a client
  asks there before relying on it. A daemon before 0.3 refuses such a post as an answer the
  question does not offer, and posts nothing. Clients of API 0.1 and 0.2 are served as before, and
  their history shows an answer in words as an answer with an empty pick.
- **An agent says which answer it recommends.** `muster msg post --option A --option B --recommend
  2` marks one offered answer as the one its author would pick. The banner and the conversation
  label it "Recommended", `muster msg read` prints `(recommended)` after it, and you can still
  pick any answer. API 0.3 carries it as `recommended` on a post, where a daemon that serves it
  lists the option `msg.post.recommended` in its Welcome.
- **An agent's effort beside its model.** A Claude Code or Codex pane now reports the reasoning
  effort its model runs at, `high` or `xhigh`, and the agent list's details show it after the model:
  "Opus 4.5 · high". Claude Code reports it through its statusline, and Codex once each turn ends.
  `muster window --json` has it in `facts.effort`, and API 0.3 in `Facts.effort`. Codex installs a
  copy of its plugin, so install it again, as `muster docs harnesses` says, to get it there.
- **A program sees who has read what through API 0.3.** The topic `TOPIC_PLACES` says where each
  member of each group on this machine has read, and a Places event follows every move, so a
  client can mark which posts each addressee has read. `muster docs api` gives the rule for a
  member who left and joined again.
- **A program reopens a pane it closed through API 0.3.** `pane.reopen` brings back a pane by its
  id or callsign, under an operation id, and `pane.close`'s answer says until when that can be
  done, so a client can offer an undo. A daemon that serves it lists `pane.reopen` in its Welcome.
- **`muster msg post --group G --answer Q TEXT`**, the question's number with no `:N`, answers #Q
  in TEXT's own words from a shell. `--answer Q:N` still picks the Nth offered answer, and `muster
  docs msg` has both.

## Under the hood

- The daemon protocol is 1.10, up from 1.9; the detection engine stays at 17. Muster hands the
  running daemon's panes to the new one on the first launch after updating, on the laptop and on a
  devenv, so running agents keep running.
- A daemon before 1.10 remembers no closed pane, so a pane closed on a machine still running one
  cannot be reopened.
- A daemon before 1.10 cannot keep an answer in words. Until a linked machine's daemon is updated,
  an answer in words that would go to it is refused, naming the machine, and nothing is sent.
- Changes to building and testing Muster itself are in the commit log, not here.
