## Behaves differently

- **Run `muster harness install codex` again on each machine running Codex 0.160.** Until you do,
  Muster refuses a Codex pane's reports. By default Codex 0.160 runs every session's hooks in one
  shared `codex app-server` process carrying the first session's `$MUSTER_PANE`, so one pane's
  hook could report as another pane, and Muster now refuses every report that comes through that
  server. The install now also runs `codex features disable daemon_auto_start`, which turns the
  shared server off for sessions started afterwards. A server already running keeps taking new
  sessions: stop it yourself with `codex app-server daemon stop`, which also ends every session in
  it.
- **`muster pane wait` exits 1 when a pane it waits on goes `stuck`** (below), naming the program
  that stopped reading, unless `--until` names `stuck`. A wait for `idle` on such a pane used to
  run until its timeout, or forever.
- **An agent in a pane is shown and addressed by the pane's name** (below). One that has not joined
  under a name of its own used to be named after its directory. It is now named after its pane and
  shown as `otter (p29te12q4t)`, so `muster pane new --name builder` names the agent too, and a
  group of two is named after its panes, `director+otter`. `--json` keeps the ids and adds a
  `called` map from each id to its name.
- **`muster msg post --to X` reads `X` as the pane verbs read `--pane`**: a pane id first, then a
  name, and a name that means more than one agent is refused, naming each. It used to match names
  before ids, and only among this machine's panes, so with an `otter` on the laptop and another on
  a devenv it silently reached the local one. `muster msg join --name` refuses a name that another
  pane already has.
- **`(off screen)` in `muster window` marks a pane in a tab the window is not showing**, which
  `(hidden)` used to. Hidden now means a pane put away with Hide Pane (below).
- **A just-started agent reads `unknown` until its screen has been read**, for about its first
  three seconds. It used to read `idle` at once, so `muster pane wait --until idle` straight after
  `muster pane new --run` answered before the program had drawn anything: past a Claude Code
  folder-trust dialog, or while a first prompt was already running. The wait now answers what the
  screen says, and nothing rings an agent before then.
- **An empty reference is refused**: `--pane ""`, `--tab ""`, `--onto ""`, `--daemon ""`, an empty
  positional pane or tab, or an empty name in `muster msg post --to`. An empty `--pane` used to
  act on the pane the keyboard was on, which could be the pane you were typing in. Leaving the
  flag out still means the pane the command runs in. A script that passes an unset variable now
  fails instead of reaching the wrong pane.
- **`muster tab rename` and `muster pane rename` refuse a name whose first word is a tab's or
  pane's id** when no `--tab` or `--pane` is given, and print the command that was meant.
  `muster tab rename t29vgmaqym CHAT NOTES` used to rename the tab the keyboard was in to
  `t29vgmaqym CHAT NOTES`.
- **A pane cannot be given the name a live agent on its machine joined messaging by**, through
  `muster pane new --name` or `muster pane rename`, since `--to` that name would then mean two
  agents. A harness `/rename` to such a name leaves the pane's name as it was.

## New

- **Every pane has a short name to go by.** The daemon picks each pane a word, such as `otter` or
  `maple`, unless somebody names it, and everything that takes a pane's id takes that name too:
  `--pane` on every verb, `muster msg post --to` and `muster msg group add`. Two machines can each
  have an `otter`, and `otter@devenv` says which, by the machine name `muster window` prints. No
  two live panes on one machine share a name, so a rename to a name another pane holds is refused.
  A pane's process is told its name at birth as `$MUSTER_PANE_NAME`. Keep the id for anything that
  must outlive the pane, since a closed pane's name is free for the next one.
- **An agent whose program has stopped reading its input reads `stuck`.** The daemon notices when
  a program it has seen reading leaves input unread for 5 seconds. `muster window` prints `stuck`
  with the program and how many bytes it left unread, the agent list paints it pink, and the agent
  asks for you with a banner; `[notifications] stuck` and `[colors] agent_stuck` change those. A
  message to a stuck agent waits, and wakes it only once the program reads again; the post says
  so. The warning for a pane that has painted nothing now names the program rather than blaming
  the pane's bridge. Interrupting the program, or ending it and resuming its session, frees it.
  This is GitHub issue #1.
- **Hide a pane with its agent running, and bring it back from a list.** Hide Pane, on a pane's or
  its row's right-click menu or in the menu bar, moves it under Hidden in the agent list, where its
  row still shows the agent's state. Clicking the row brings it back in a tab of its own. `muster
  pane hide`, `muster pane show --pane P` and `muster pane new --hidden` do the same from the CLI.
  A hidden pane stays hidden across the app quitting and the daemon restarting.
- **Make a pane quiet, so nothing about it interrupts you.** Quiet Pane, on the same menus, or
  `muster pane quiet [--off]`: a quiet pane raises no banner, the chord to whichever agent is
  asking passes it over, and its bell does not bounce the Dock. Its state still shows. Hidden and
  quiet panes are meant for an agent that runs helpers in panes, and
  `muster pane new --hidden --quiet` starts one that way.
- **Upgrade Muster from its own menu, or with `muster upgrade`.** Upgrade muster, in the app menu,
  opens a tab running `brew upgrade --cask amterp/tap/muster`. The tab's pane belongs to the
  daemon, so brew keeps running when it quits the app, and the tab opens the app again once brew
  is done. It refuses, saying why, for any Muster that Homebrew did not install. 0.14.0 has
  neither, so getting to 0.16.0 still takes running `brew upgrade --cask amterp/tap/muster`
  yourself.
- **A pane on a machine Muster cannot reach reads `unreachable`**, with its last state beside it:
  `unreachable 2d  label  (was blocked)` in `muster window`, for a pane unreachable for 2 days, and
  `last_state` in `--json`. It drops its title, context ring and other claims about the present,
  asks for nobody, and never satisfies a `muster pane wait`. A devenv that rebooted used to leave
  its panes reading `idle` and `waiting` for as long as the window stayed open.
- **A window starts its daemon again after the daemon dies**, on this machine or on a devenv, so a
  devenv that rebooted comes back without relaunching Muster. Its panes return as after any daemon
  restart: the tree and each pane's directory, and the agents whose harness reported a session
  resumed in it. A daemon whose `socket` you named in a `[[daemon]]` block is only dialed, as at
  launch. Nothing is started on a devenv while its SSH connection is down.
- **A group held up on a member is noticed, and its poster told why.** Once a message has waited
  unread for 2 minutes on a member whose agent is not working, Muster wakes the member once more
  if its last wake never landed. If there was no wake to retry, or the retry does not move it,
  Muster posts in the group as `@muster`, telling whoever posted the unread message why the member
  has not answered: a program that stopped reading, a dialog it sits at, or a wake it never acted
  on. The run log records each stall as `msg.group.stalled`.
- **`muster pane new`, `rename`, `close`, `hide`, `show` and `quiet` work with no window**,
  against this machine's daemon, so an agent on a devenv can start and close workers while the
  laptop sleeps or has quit Muster. They used to wait 10 seconds for a window and exit 3. A pane
  made with no window splits the caller's pane, or the one `--pane` names, and a window that comes
  back draws it there.

## Fixed

- **Codex 0.160's screens before a session starts read `blocked`, not `idle`**: the hooks review,
  folder trust, update and sign-in screens. `muster pane wait --until idle,blocked` used to return
  `idle` there, and a brief posted then landed behind the dialog.
- **`muster harness install codex` no longer fails after Muster is updated** with "marketplace
  'muster' is already added from a different source". It now removes the registration an earlier
  Muster install left before adding its own. One added from anywhere else, such as a source
  checkout, is left alone.
- **A daemon that accepted a connection and never answered held `muster msg` forever**, and the
  pane verbs that answer with no window. These commands now give up after 5 seconds, report the
  daemon unreachable and exit 3.
- **A Claude Code turn that ended on a long shell command read `working` for good**, and every
  message to that agent waited with it. Claude Code 2.1.299 draws a finished Bash call as one row
  cut off with `…`, which Muster took for its spinner. If you worked around this with an override
  at `~/.muster/agent-detection/claude.toml`, delete it after updating.
- **Claude Code's first-run screens read `blocked`**: the theme picker, the security notes and the
  login picker read `idle` before.
- **`muster pane wait --pane <name>` finds the pane through a window.** Only an id worked there,
  though every other `--pane` took a name.
- **A session restarted in its pane can rejoin a group under its old name.** `muster msg join
  --name` refused it, because the pane's new agent made the dead session look alive.
- **`muster msg post --to <pane name>` is no longer refused as ambiguous** when the other match is
  a participant that has gone and whose pane has closed.
- **`muster msg post --to` with a pane's title says which pane it is.** A title such as
  `BUILD LEAD` was refused as a malformed name; the refusal now names the pane showing it, by id.
  A title is not an address, since the program in the pane rewrites it as it works.
- **Shift+Tab reaches a program that turned on the kitty keyboard protocol**, as Claude Code does,
  so it cycles Claude Code's permission modes. Muster sent it as a plain Tab there; a plain
  shell was unaffected. Shift+Return keeps its shift the same way. `muster pane send --key
  shift+tab` presses it from the CLI.
- **A refused Rename Tab says why** in a sheet, as the pane menus do. It used to close with nothing
  said.
- **Deleting an agent-detection override always takes effect.** One saved while the daemon was
  starting, or saved and deleted between two of the daemon's looks, kept applying.

## Under the hood

- The daemon protocol is 1.5, and agent detection engine 14: an agent's manifest can name its
  harness's shared server (`[server]`), whose reports are refused rather than given to a pane.
  Muster hands the running daemon's panes to the new one on the first launch after updating, on
  the laptop and on a devenv, so running agents keep running.
