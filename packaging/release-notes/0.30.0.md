## Added

- **The agent list outlines every tab's panes.** The caption stays visible when the window has
  one tab, and its chevron folds the tab. A tab color fills its caption and colors its outline.
  A pane color marks its callsign in the list and in the pane header. Right-click the tab caption
  or agent row and open **Color** to set or clear its color.
- **Muster supports Antigravity.** It reads Antigravity's composer, recognizes its trust and
  approval dialogs, and can rename, clear, compact and resume an Antigravity conversation. A
  plugin reports the conversation, its turns and its context, and `muster` installs and refreshes
  it as it does the other harnesses' adapters. A turn that ends with a shell task still running in
  Antigravity's task panel reads `waiting` until the task finishes.
- **The API reports session transcripts and where each post went (API 0.7).** A pane's live
  session carries the path of its transcript, so a client can pair the two, and a post's reply
  gives one routing outcome per recipient, so a held wake can be told from a missing route.

## Fixed

- **A closed pane no longer holds a group up.** Agents were woken hours
  or days late with "has not read ... no agent is in its pane any more" about panes they had
  closed themselves. Who closed a pane is now kept with its messages, and a pane closed more than
  an hour ago holds nobody up.
- **An agent can wait on your answer.** `report --waiting ... --until-message-from @human` was
  refused with "nobody here ... is called @human". A message from you now ends that wait, from any
  machine.
- **Panes come back from a reboot in their sessions.** A machine shutting down ends the agents
  before the daemon, and the daemon dropped every pane's saved resume in that gap, so the panes
  came back as shells. A resume now stays saved for 30 seconds after its agent leaves. The
  daemon's log now says when a resume is dropped and why, and, at start, when the daemon before it
  was killed or crashed rather than stopping.
- **A restarted Codex can be restarted again at once.** After Restart Agent, the pane showed no
  session until the resumed agent first reported one, which Codex does only at its first prompt,
  so Restart Agent stayed disabled until somebody typed. The pane now keeps showing the session it
  was restarted with until the agent reports another or leaves.
- **A stuck pane names its agent, not the script that started it.** A Codex started through a
  wrapper script read "(rad has not read 1831 bytes of input)". The label now names the agent the
  pane's detection found.
- **A Claude Code sub-agent's compaction no longer marks the whole pane compacting.** Claude Code
  runs its compaction hooks for sub-agents too, and Muster's hooks reported each one as the
  session's. They now skip a sub-agent's. This follows the hook input Claude Code documents; it
  was not observed live.
- Clicking a helper keeps its row under its maker. Showing the helpers' tab leaves the agent
  list's rows and numbered shortcuts in place.
- **A stray ssh master on Muster's control path no longer holds a machine's panes unreachable.**
  After Muster's own ssh master died, another master could take over its control path without
  the forward to the machine's daemon. It answered `ssh -O check`, so Muster read the tunnel as
  up and never reopened it, and every pane on that machine stayed `unreachable`. Once its ssh
  has exited, Muster now also tries the forwarded socket. If nothing listens there, it ends
  whatever holds the control path and reopens the tunnel.
- **Reopen Closed Pane brings a Claude Code session back when its startup report was missed.**
  Only Claude Code's `SessionStart` hook told Muster the session's id, so a pane whose report
  never arrived reopened as a plain shell. The `Stop` hook now sends the id at the end of each
  turn. A startup report that fails also leaves its error in Claude Code's debug log
  (`claude --debug`) instead of being discarded. Sessions take this up when restarted.
- **Scrolling over an idle agent no longer makes it read `stuck`.** Wheel and click reports the
  agent had not read yet counted as unread input, so a Codex pane at an idle prompt could read
  `stuck`, and a stuck pane drops clicks. Only keys, pastes and doorbell rings count now. On
  Linux, about 4 KiB of pointer reports queued behind unread keys can hide those keys, so a
  program that really hangs there is read `stuck` only after the next key (`muster docs limits`).
- **A script that outlives its pane no longer posts as you.** `muster msg post` run with a
  closed pane's `$MUSTER_PANE` was recorded as coming from `@human`. It is now refused, and so
  is a `msg read` that would have marked your messages read. `muster msg --as NAME` still posts
  as NAME from there, and `join --name` still joins.
- **Codex's "Approaching rate limits" selector reads `blocked`.** A pane at that selector read
  `waiting` or `idle`, and a message for it was described as held behind a draft. The pane now
  reads `blocked` even when it has declared a wait, and `muster msg post` and `muster msg who`
  say the message waits on a dialog. The screen was rebuilt from a report and Codex's own tests,
  not recorded from a live selector.
- **`muster pane send --key` returns once the pane has redrawn.** A key sent to a dialog
  returned before the dialog moved, so the next key or `muster pane read` acted on the old
  screen: three Downs in a row could move the selection once. After its last key, a send with
  keys now waits until the pane's text has changed and been still for 100 ms, or 300 ms when
  nothing changes, and about a second at most while the pane keeps printing. It cannot tell
  which key a change answers, so send one key per command when each must land before the next.
  Sends of text alone are as fast as before. The same holds for the API's send.

Changes to the test suites and the build that do not reach an installed Muster are not listed.
