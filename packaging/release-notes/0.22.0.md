## New

- **Paste an image into an agent on another machine with Ctrl+V.** With an image on the Mac's
  clipboard, Ctrl+V in a Claude Code or Codex pane on a devenv sends the image to that machine and
  pastes its path, which the agent attaches as it would a local Ctrl+V. What you type meanwhile
  waits until the image lands, under a "Pasting image…" note, and Esc or Ctrl+C cancels; on a slow
  link the wait can last up to two minutes. Everywhere else Ctrl+V reaches the program as before:
  a pane on this Mac, whose agent reads the clipboard itself, a shell, vim, a dialog, or a
  clipboard holding text. ⌘V on a clipboard holding only an image pastes it the same way, on
  either machine. Pasted images are kept for seven days in a private directory beside the
  daemon's socket, up to 1 GiB in all, and an image over 15 MiB is refused.
- **Cmd-click opens a web link while the program has the mouse.** Claude Code and Codex both turn
  on mouse reporting, so until now a link in their panes, on this Mac or a devenv, opened only with
  Shift held. Ordinary clicks still go to the program.
- **A wait can name whom it waits on.** `report --waiting "<what>" --until-message-from <pane>`
  ends the wait when that pane's message wakes the agent, so a worker waiting on its reviewer
  reads idle once the review arrives. A wake from anyone else leaves the wait standing.
- **A maker hears about a helper that has waited ten minutes.** Once per declared wait, Muster
  tells the maker what the helper is waiting on and how to look at it. The wait itself stays.
- **What covers an idle agent's prompt is named.** `muster window` and `pane wait` show `(prompt
  covered by ...)` when a notice or menu sits over the prompt, such as Claude Code's "Heads up"
  tip, and `--json` has it as `prompt_covered_by`. A message waits rather than being typed into the
  notice, and `muster docs limits` gives the keys that clear it.

## Changed

- **Codex is woken by typing again, no longer through `codex queue`.** A queued wake could reach a
  conversation the pane no longer showed after `/new`, and come back after a resume for a message
  already read. A Codex with a draft in its composer now gets its wake once the draft is sent or
  cleared, as Claude Code does. After `/new` the old conversation can still read the pane's
  messages if it runs again, so restart a pane for a new assignment rather than using `/new`.
- **Claude Code waiting for its background agents reads idle.** On "Waiting for N background
  agents to finish" Claude Code takes typed input and `/compact`, so Muster rings it and compacts
  it there rather than waiting for the background agents.
- **A Claude Code, Codex or OpenCode pane reads `unknown` until the agent draws its screen**, rather
  than idle once a three-second grace ends, so `pane wait --until idle` keeps waiting through a
  slow first launch. Harnesses whose manifest has no idle rule keep falling back to idle.
- **The window no longer stops while a slow daemon answers** New Tab, Split, Leave Group, Delete
  Group, loading a conversation's earlier messages, pausing a group, or a post to a conversation.
  Each of these could freeze it for ten seconds at a time while a devenv was slow over ssh.

## Under the hood

- The daemon protocol is 1.11, up from 1.10, and the detection engine is 18, up from 17. Muster
  hands the running daemon's panes to the new one on the first launch after updating, on the
  laptop and on a devenv, so running agents keep running.
- A daemon before 1.11 refuses `--until-message-from`, and cannot take a pasted image: until a
  linked machine's daemon is updated, an image paste into one of its panes fails and pastes
  nothing.
- Changes to building and testing Muster itself are in the commit log, not here.
