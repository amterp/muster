## New

- **An API for other programs.** A program that is not an agent in a pane, such as a dashboard, a
  phone's server or a notifier, can now read and act on Muster through the daemon's socket:
  protobuf with a schema and a version of its own, API 0.2 (MIP-10,
  `docs/mip/0010-api-for-other-tools.md`). One subscription gives a snapshot and then numbered
  events for every pane and its agent's state, every linked machine, every group and its posts, and
  what waits on you, including whether you are at the desk. A program can post and answer as you,
  mark read what it showed you, start an agent in a new pane, read a pane's text, and type into,
  close, compact or restart a pane. A client sees the machine whose daemon it connected to; other
  machines' panes come later. A subscription ends with its connection, so a client that
  reconnects subscribes again and gets a fresh snapshot, while `msg.history` pages a group's log on
  from the last entry the client holds. An operation id makes a retried post or new pane happen
  once. `muster window --json` stays written for
  agents and scripts and makes no promise to a program; the API does. Until Muster's 1.0 the API
  is 0.x, and a minor may break clients; release notes will say when one does.
- **`muster docs api`** is where to start writing such a program, and `muster docs api --schema`
  prints the schema this build speaks, to generate bindings from in any language.
  `extras/api-client-go` is a client generated from that schema alone.
- **A post a program made shows the program beside its author**: "you via foreman" in the banner
  and the conversation, and "Alex (@human) via foreman" in `muster msg read` and `log`, with `via`
  in their `--json`.
- **A question answered elsewhere, such as from a phone, takes its banner down**, or never raises
  it. A banner holding a reply you are writing keeps it.
- **`muster msg ack G --through N`** marks your messages in group G read through #N and no further,
  as a program does through the API. It always acts for you, and an agent running it is refused
  and told to use `read`.
- **`muster window` with no window open shows how long each agent has held its state**, and
  `--json` gives `since` in seconds, as a window's does. A window now dates each state from when
  the daemon saw it begin, so a pane already idle when the window opened no longer reads as idle
  since then, and two windows agree. A state the daemon did not see begin, as after a restart
  resumed the agent, has no time with no window open.

## Fixed

- **A Claude Code subagent no longer takes its parent's unread messages.** Claude Code runs a
  subagent's tool hooks in its parent's pane, so the messaging hook could hand the parent's
  messages to the subagent. Needs the updated messaging hooks (Under the hood, below).
- **Acting as @human from an agent's pane keeps you and the agent apart.** The agent's pane and
  inbox were given to you, so its later commands could read your unread messages and stall checks
  could type your wakes into its prompt. Joining a remote group as @human from an agent's pane no
  longer removes the agent from that group.
- **A request waiting on another machine no longer holds up its connection**, which could make a
  window's later reads of panes and messages time out.

## Under the hood

- The daemon protocol is 1.9, up from 1.8; the detection engine stays at 17. Muster hands the
  running daemon's panes to the new one on the first launch after updating, on the laptop and on a
  devenv, so running agents keep running.
- The messaging hooks for Claude Code in `extras/claude-code/messaging-hooks.json` run `muster msg
  read --if-unread --from-hook`. They are copied into settings by hand, so copy the new
  `PostToolUse` command over the old one.
- Changes to building and testing Muster itself are in the commit log, not here.
