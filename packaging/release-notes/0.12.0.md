## Behaves differently

- **`cmd+1` to `cmd+9` go to a tab, and the next press goes to a pane inside it.** Keep `cmd` down
  after `cmd+2` and press `3` to land on that tab's third pane; let go to stop at the tab. A window
  holding one tab still numbers its panes, one press each. This was `numbered_chords =
  "tab_then_pane"`, and it is now the only scheme: the old one, where `cmd+3` was the third pane
  down the whole agent list, is gone. A config naming `numbered_chords = "panes"` is refused, and
  the whole file with it, saying what replaced it; delete the line. One naming `"tab_then_pane"`
  still loads. Every row in the agent list shows the chord that reaches it.
- **`muster focus --place N` goes to the pane `muster window` prints at place N**, counted down the
  whole window. With `tab_then_pane` set it used to act as `cmd+N` and reach the Nth tab.

## New

- **`cmd`-click a link in a pane to open it**, an address on the screen or an OSC 8 hyperlink. Web
  and mail links open on this Mac, from a devenv pane too. A path opens only from a pane on this
  Mac, since from a devenv it names a file over there. A file that would run code when opened, or
  a link hiding invisible characters, is refused with a beep, and a hyperlink to another app's
  scheme asks first.
- **Drag the agent list's edge** to make it wider or narrower, from 140 to 480 points. Each window
  remembers its own width across a relaunch.
- **A color swatch on each row says which machine a pane is on**, while a window is attached to
  more than one. A machine's color is drawn from its `id`, so it is the same in every window; a
  `color` in its `[[daemon]]` block picks another when two machines land on the same one.
- **`muster msg post --to` reaches an agent or a pane on another machine** with no group shared
  first, making the group of exactly those members as it does on one machine. `name@machine` names
  one on a particular machine, and `group add` finds members the same way.
- **A group's policy can name a member on another machine** as `name@machine`, in its ring, allow
  and membership, so a devenv agent can direct a council kept on the laptop, or join a group whose
  membership is not `*`.
- **`muster msg` in your own shell on a devenv does what it does on the laptop.** While the devenv
  is linked to the laptop, reading, waiting, joining and posting there are carried to the laptop
  and done as you, instead of being refused with a pointer to the laptop.

## Fixed

- **A slow ssh check no longer drops every devenv pane.** A check that times out is asked again
  before Muster ends the connection; only a second timeout in a row ends it.
- **Devenv panes come back as soon as a reconnect lands**, rather than about 15 seconds later.
- **Quitting ends Muster's ssh connections**, and a starting Muster ends ones an earlier Muster
  left running. A left-over connection kept the old window answering on the devenv, so `muster
  window` in a pane there could reach a window that had quit.
- **A `ControlMaster auto` in your `~/.ssh/config` can no longer take over Muster's connection** to
  a devenv.
- **A devenv daemon Muster adopts gets its `muster` CLI** when the machine has none, so `muster msg`
  works in its panes.
- **The agent list's chord digits are readable at a glance**, in light and dark appearance.

## Under the hood

- The daemon protocol is 1.2. Muster hands the 0.11.0 daemon's panes to the new one on the first
  launch after updating, on the laptop and on a devenv, so running agents keep running.
