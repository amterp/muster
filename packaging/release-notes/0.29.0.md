## Fixed

- **A numbered chord that switches tabs keeps its first press.** Pressing ⌘1 and then ⌘2, from a
  tab other than the first, could land the keyboard on tab 2 instead of the first tab's second
  pane. When ⌘1 brought tab 1 on screen, the pane under a pointer that had not moved reported
  pointer motion, and that motion took the first press back. Pointer motion with no button held,
  and a key coming up, now leave a chord armed; a click, a drag or a keystroke still ends it. The
  cause was read from run logs rather than watched, so the run log now records `chord.disarmed`
  with the kind of request that ended a chord early, and never its contents.
- **Clicking a row in the agent list no longer strands the keyboard there.** Clicking the row of
  the pane that already had the keyboard left the keyboard on the list: keys stopped reaching the
  pane, digits moved the list's highlight, and clicking the terminal did not bring it back. The
  agent list no longer takes the keyboard, and a click on a pane takes it back from whatever view
  holds it, a banner included.

Changes to the test suites and the build that do not reach an installed Muster are not listed.
