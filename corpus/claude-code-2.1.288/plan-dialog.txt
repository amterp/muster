Which hooks Claude Code fires at plan mode's dialog asking whether to go ahead with a plan, and how the dialog's question wraps in a narrow pane.

Recorded 2026-10-03 on macOS 26.4.1 / arm64, Claude Code 2.1.288 running Haiku 4.5, in a
pseudo-terminal driven by a scratch script built on tools/detection-capture.py, with a hook on
every event writing the event's name. Asked for a one-line plan and to call ExitPlanMode at once,
started once with --permission-mode plan (100x30) and once bypassing permissions and entering
plan mode by its EnterPlanMode tool (160x50, and 64x45).

Hooks, in order, from the request to the dialog, both ways:
    UserPromptSubmit
    PreToolUse ToolSearch, PostToolUse ToolSearch
    PreToolUse EnterPlanMode, PostToolUse EnterPlanMode    (the second way only)
    PreToolUse Write, PostToolUse Write                    (the plan file)
    PreToolUse ExitPlanMode
    PermissionRequest ExitPlanMode
    the dialog is up
    Notification, notification_type "permission_prompt": "Claude Code needs your approval for the plan"
After approving with Return:
    PostToolUse ExitPlanMode, then the plan's own tool calls, then Stop

The dialog's last lines, 100 columns wide:
     Claude has written up a plan and is ready to execute. Would you like to proceed?

     ❯ 1. Yes, auto-accept edits
       2. Yes, manually approve edits
       3. Tell Claude what to change
          shift+tab to approve with this feedback

The first option reads "Yes, and switch to BYPASS PERMISSIONS (no further prompts) for this
session" in a session bypassing permissions, and "Yes, and use auto mode" where auto mode is on.

64 columns wide, bypassing permissions, the question breaks inside its last words:
     Claude has written up a plan and is ready to execute. Would
     you like to proceed?
claude.toml 2026.10.03.1 read the wide dialog blocked, by a low rule matching "would you like to"
and "yes" on one line, and the narrow one idle, by the title "✳ <task>": nothing else on screen
named a dialog.
