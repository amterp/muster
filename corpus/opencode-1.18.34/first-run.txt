Which free model OpenCode answers on with no credentials reachable, and what it does with a pasted
line and its Return in one write.

Recorded 2026-10-04 on macOS 26.4.1 / arm64. Every run unset each environment variable whose name
holds KEY, TOKEN, SECRET, PASSWORD or CREDENTIAL, and pointed XDG_DATA_HOME, XDG_CONFIG_HOME,
XDG_STATE_HOME and XDG_CACHE_HOME at scratch folders, so no stored login or API key could be used.

opencode 1.3.15, the installed build (~/.opencode/bin/opencode):
    $ opencode models opencode
    opencode/big-pickle  opencode/gpt-5-nano  opencode/minimax-m2.5-free
    opencode/nemotron-3-super-free  opencode/qwen3.6-plus-free
    $ opencode run -m opencode/minimax-m2.5-free "Reply with the single word hi."
    Error: Model minimax-m2.5-free is not supported
    $ opencode run -m opencode/nemotron-3-super-free ...   (and qwen3.6-plus-free, gpt-5-nano)
    Error: Model not found: opencode/<model>.
    $ opencode run --format json -m opencode/big-pickle ...
    {"type":"error", ... "statusCode":403, ... "FreeTierError","message":"Error from provider
    (Console): OpenCode's free tier can only be used from within OpenCode"}
    the TUI started with -m opencode/big-pickle drew "Build  Big Pickle OpenCode Zen", and the
    request's turn ended with the same FreeTierError
So -m is honored once no credential is in the environment. The earlier runs that drew a Google
model had GEMINI_API_KEY in theirs; whether that is why was not checked. Either way, the free
tier refuses 1.3.15.
