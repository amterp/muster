What Codex 0.154.0 does with `/rename` typed into its composer, and where a session's name is
kept.

Recorded 2026-10-03 on macOS 26.4.1 / arm64, codex-cli 0.154.0 running gpt-5.6-luna at low
reasoning effort, -a on-request -s read-only, in a 100x30 pseudo-terminal driven by a scratch
script built on `tools/detection-capture.py`. `~/.codex/session_index.jsonl` was read before and
after each step; only the lines added are shown, ids shortened.

Idle at a fresh composer, before any turn, one write holding a bracketed paste and a Return:
    ESC[200~/rename early nameESC[201~ CR
    {"id":"01a1029b-…","thread_name":"early name","updated_at":"…16:32:11Z"}

A turn ("Reply with the single word hi."): nothing added.

After the turn, pasted the same way:
    ESC[200~/rename 🤖 BESC[201~ CR
    {"id":"01a1029b-…","thread_name":"🤖 B","updated_at":"…16:32:22Z"}

Typed as keys, "/rename typed name", then Return 1.5 s later:
    {"id":"01a1029b-…","thread_name":"typed name","updated_at":"…16:32:27Z"}
    title: "typed name | m3out"

Each rename appends a line; the last line for an id is its name.

A second session, never renamed, after one turn ("Reply with the single word hi."):
    {"id":"01a1029c-…","thread_name":"Reply with hi","updated_at":"…16:32:48Z"}
    title: "Reply with hi | m3bout"
Codex names a session itself after its first turn, in the same file and the same form as a
rename: nothing there tells the two apart.
