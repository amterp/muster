How Codex 0.154.0 counts the context it has used, against the token counts in its transcript.

Recorded 2026-10-03 on macOS 26.4.1 / arm64, codex-cli 0.154.0 running gpt-5.6-luna, in a 100x30
pseudo-terminal. The session's transcript, ~/.codex/sessions/<date>/rollout-<time>-<id>.jsonl,
holds an event_msg of type token_count after each model response; `rollout-tail.jsonl` beside this
file is the end of one, scrubbed of its rate limits.

While a draft sat in the composer, Codex's footer said "97% context left". The transcript's last
token_count then:
    last_token_usage.total_tokens 19072, model_context_window 258400
    used as a share of the window:                    19072 / 258400 = 7.4%, 92.6% left
    past a baseline of 12000, as Codex's own code does: (19072 - 12000) / (258400 - 12000) = 2.9%,
                                                       97.1% left - what the footer said
Each token_count line is about 1 KB; the transcript grows with every tool call's output, so a
hook reads its tail, not the whole file.
