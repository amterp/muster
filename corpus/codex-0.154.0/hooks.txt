Which hooks Codex 0.154.0 fires, in what order, for a turn, a tool call, an approval, Esc and a message queued while it works.

Recorded 2026-10-03 on macOS 26.4.1 / arm64, codex-cli 0.154.0 (Homebrew cask) running
gpt-5.6-luna at low reasoning effort, in a 100x30 pseudo-terminal driven by scratch scripts built
on tools/detection-capture.py. Every event had a hook writing its JSON input and the value of an
environment variable set only on the codex process. The hooks were a project's .codex/hooks.json
in a trusted folder, or the same groups passed as -c hooks.<Event>=[...], with
--dangerously-bypass-hook-trust. Session ids are shortened to <session>, paths to <folder>.

Starting, then "Reply with the single word hi.":
    (nothing at launch)
    SessionStart      source "startup", permission_mode "default", model "gpt-5.6-luna",
                      transcript_path "~/.codex/sessions/2026/10/03/rollout-2026-10-03T09-44-16-<session>.jsonl"
    UserPromptSubmit  prompt "Reply with the single word hi.", turn_id
    Stop              last_assistant_message "hi", stop_hook_active false
Every hook's environment held the variable set on the codex process.

A SessionStart group with matcher "startup|clear", one with "resume" and one with none: the first
and the last ran.

A SessionStart hook printing "The first secret word is PINEAPPLE." and another printing
{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"The second secret word is MANGO."}},
then "What secret words were you told, if any?": the model answered "PINEAPPLE MANGO".
